# 뉴비맵 (Newbiemap) — 모바일 앱 데모

> 조금 돌아가더라도, 나에게 운전 부담이 적은 길로.

운전이 서툰 사람이 **자기에게 부담이 적은 길**을 고르도록 돕는 내비게이션 앱의 **프런트엔드**입니다. 휴대폰(세로 화면)만 기준으로 만들었습니다.
React Native + Expo + TypeScript 로 만들었습니다. 이 저장소에서 확인한 것은 **웹 미리보기(휴대폰 크기), 네이티브 번들 컴파일, Android 에뮬레이터(Expo Go)** 까지이고, 실기기와 iOS 는 아직 확인하지 않았습니다(10장).

> ⚠️ **데이터는 시연용입니다.** 지도·장소·경로·시간·통행료·교통량·추천·개인화는 모두 **모의 데이터/규칙**이고,
> 주행 안내는 선택한 경로를 따라 움직이는 화면입니다(실제 위치를 쓰지 않음). 실제 주행에 사용하지 마세요.
> '운전 부담이 낮음'은 안전하거나 사고가 없다는 뜻이 아닙니다. 앱은 안전 점수를 만들지 않습니다.
> 화면마다 '데모' 표시를 붙이지 않고, 아래 `시연 안내 지점` 에서만 알립니다(9장).

이 폴더(`mobile/`)는 기본으로 백엔드(FastAPI, `backend/`) 없이 **모의 데이터로** 동작합니다. 서버·API 키·로그인이 필요 없습니다.
설정 하나로 장소·경로를 백엔드(`/v1`)에서 받는 **백엔드 모드**로 바꿀 수 있습니다(1장).

## 1. 실행

필요한 것: **Node.js 20.19.4 이상**(React Native 0.86 의 요구 범위: 20.19.4+ / 22.13+ / 24.3+. 개발 환경은 Node 24.21 / npm 11.19), 휴대폰에서 열 때는 Expo Go 앱 또는 개발 빌드.

```bash
cd mobile
npm install
npm run web          # 웹 미리보기: http://localhost:8081  (휴대폰 크기 창에서 보세요. PC 폭 레이아웃은 만들지 않았습니다)
npm start            # Expo 개발 서버 — QR 로 Expo Go 에서 열기 / i(iOS) · a(Android) 키로 시뮬레이터 열기
npm test             # 단위 테스트 (jest, 15개 파일 / 256개 테스트)
npm run typecheck    # tsc --noEmit
```

- 단일 테스트: `npx jest src/domain/__tests__/burden.test.ts`, 이름으로: `npx jest -t "비보호 좌회전"`
- **백엔드 모드**: `mobile/.env.local`(커밋되지 않음)에 아래를 넣고 개발 서버를 캐시를 비워 다시 시작합니다(`npx expo start -c`).
  ```
  EXPO_PUBLIC_DATA_SOURCE=backend
  EXPO_PUBLIC_API_BASE_URL=http://localhost:8000   # 선택. 없으면 Expo 개발 서버가 떠 있는 PC 의 8000 포트
  EXPO_PUBLIC_KAKAO_JS_KEY=<카카오 JavaScript 키>   # 선택. 있으면 실제 지도(카카오맵)를 씁니다
  ```
  백엔드는 `backend/.env` 에 `GRAPH_PATH=data/seoul.json`(서울 전체 실제 도로망, 만드는 법은 backend/README.md)을 넣고 `cd backend && uvicorn app.main:app --port 8000` 으로 띄웁니다. `GRAPH_PATH` 가 없으면 백엔드가 광주 가상 격자를 써서 앱의 시연 지점으로는 경로를 찾지 못합니다(서비스 지역 아님). Android 에뮬레이터는 `adb reverse tcp:8000 tcp:8000` 후 `localhost` 로 붙습니다(또는 `http://10.0.2.2:8000`).
  실기기 Expo Go 는 앱을 받아 온 PC 주소로 백엔드에 붙으므로 와이파이·핫스팟을 바꿔도 `EXPO_PUBLIC_API_BASE_URL` 을 고칠 필요가 없습니다(백엔드는 `--host 0.0.0.0` 으로 띄웁니다).
  이 모드에서는 출발지가 강남역이고, 목적지는 카카오 검색으로 서울 안 어디든 고를 수 있습니다. 추천 지점은 강남 일대 역 4곳과 잠실·여의도·서울역·홍대입구입니다(`services/backend/samplePlaces.ts`, 좌표는 역 부근의 대략적인 지점). 지도는 카카오 키가 있으면 카카오맵, 없으면 경로 모양만 그리는 임시 지도입니다(5장). REST·Admin 키 같은 비밀 값은 이 파일에 넣지 않습니다(번들에 그대로 들어갑니다). 카카오 JavaScript 키는 등록한 도메인에서만 동작하는 공개용 키라 예외입니다.
  카카오맵을 쓰려면 카카오디벨로퍼스에서 앱의 **카카오맵을 활성화**하고, JavaScript 키의 **JavaScript SDK 도메인**에 `http://localhost` 를 등록합니다(WebView 가 지도 페이지를 이 주소로 띄웁니다). 무료 쿼터는 개발자 계정에서 처음 활성화한 앱에만 있습니다.
- 휴대폰의 Expo Go 가 SDK 57 을 지원하지 않으면 개발 빌드(`npx expo run:android` / `npx expo run:ios`)가 필요합니다.
- 처음 켜면 온보딩이 나옵니다. 처음 상태로 돌아가려면 **설정 → 모든 사용자 데이터 삭제** 를 쓰세요.
- 의존성 버전은 `package.json` 에 고정했습니다. 새 패키지는 `npx expo install <이름>` 으로 SDK 에 맞는 버전을 설치하세요.

## 2. 무엇이 실제이고 무엇이 모의인가

| 영역 | 구분 | 설명 |
|---|---|---|
| 화면·이동·로딩/빈/오류/재시도 상태 | **실제** | 모든 화면과 상태 전환이 실제 코드로 동작합니다. |
| 온보딩(3단계)·운전 성향 설정·동의 | **실제** | 나중에 설정에서 모두 바꿀 수 있습니다. 건너뛰어도 쓸 수 있습니다. |
| 설정·기록·평가·개인화 결과 저장/삭제 | **실제** | 이 기기 안(AsyncStorage / 웹은 localStorage)에만 저장합니다. 앱을 다시 켜도 남습니다. **암호화하지 않습니다.** |
| 지도 | **모의** | 가상의 지역 '새싹시'를 SVG 로 그린 지도입니다(주요 도로 + 보기용 골목·건물). 끌기·확대·경로 선택이 됩니다. 지도 오른쪽 아래에 작게 '시연용 지도'가 보입니다. |
| 장소 검색 | **모의** (백엔드 모드: 백엔드 검색) | 준비된 장소 9곳 안에서만 찾습니다. 없는 장소를 만들어 내지 않으며, 검색 목록 아래에 "시연용이라 일부 장소만 검색돼요"라고 알립니다. 백엔드 모드에서는 `/v1/places/search`(카카오 로컬, 정확도순이되 출발지 근처 우선)를 쓰고, 서버에 키가 없으면 시연 지점 안에서만 찾습니다. 도로망 범위 밖 결과는 '경로 안내 지역 밖이에요'로 표시하고 고를 수 없게 합니다. |
| 경로 후보·도로 특성·시간·통행료·교통량 | **모의** (백엔드 모드: 백엔드 도로망) | 가상 도로망에서 같은 입력이면 항상 같은 값을 계산합니다(결정적). 실시간 교통이 아닙니다. 백엔드 모드에서는 `/v1/routes/search` 가 강남 일대 실제 도로망(OpenStreetMap)으로 계산합니다. 도로 모양·일방통행·도로 이름은 실제이지만 차로 수 등 일부 속성만 있고, 보호구역·사고다발 자료는 없습니다(정보 없음). |
| 경로 추천·'예상 운전 부담' | **모의 규칙** | 단순한 규칙입니다. 실제 AI 모델이나 검증된 난이도 알고리즘이 아닙니다. |
| 개인화 | **모의 규칙** | 사용자가 직접 평가하고 동의한 경우에만, 고른 요소의 회피 정도를 조금 조정합니다. 직접 정한 값이 항상 우선합니다. |
| 주행 안내 | **경로 위 재생** | 선택한 경로를 따라 움직이는 화면입니다(기본 14배속). GPS·위치 권한을 쓰지 않습니다. |
| 로그인·서버·클라우드 동기화·백그라운드 위치·LLM | 없음 | 이번 범위에 넣지 않았습니다. |
| 실제 경로 엔진·도로 데이터·추천 모델 | 없음 | 후속 팀의 영역입니다. 연결 지점은 5장에 있습니다. |

앱 안의 **설정 → 앱 정보 → 시연 안내** 화면에도 같은 내용이 있습니다.

## 3. 화면과 흐름

```
온보딩(환영 → 질문 3개 → 요약·동의) ─▶ 홈(지도 + 내 운전 성향 + 갈 만한 곳) ─▶ 검색 ─▶ 경로 비교(3개) ─┬▶ 경로 상세 ─▶ 안내 시작
                                                                                              └▶ 안내 시작 ─▶ 도착·평가
                                   └ 탭: 지도 · 주행 기록(목록·상세·삭제) · 설정(성향·동의·삭제·앱 정보)
```

- **홈**: 지도 위에 검색창과 출발지, 아래 시트에 '내 운전 성향' 요약(눌러서 바꾸기)과 갈 만한 곳(최근 목적지가 있으면 그것). 시트는 끌거나 손잡이를 눌러 접고 펼 수 있고, 펼치면 지도가 너무 좁아지는 작은 화면에서는 접힌 채로 시작합니다.
- **경로 비교**: 경로 3개(A 가장 빠른 길 / B 고속도로 / C 회전이 적은 길). 시트 맨 위의 **요약 줄**에서 세 경로의 시간·추가 시간·예상 운전 부담을 한눈에 견주고, 아래 카드마다 시간·추가 시간·**예상 운전 부담(낮음/보통/높음)**·이유 2~3개·감수할 점이 1개 이상 보입니다.
  카드를 눌러 **선택**하는 것, 앱이 **추천**한 경로(맞춤 추천 배지), **안내 시작**(아래 버튼)은 서로 다른 동작입니다. 지도의 경로 칩이나 요약 줄로 고르면 그 경로의 카드로 스크롤합니다. 화면이 좁거나 글자가 커서 폭이 모자라면 버튼이 세로로 쌓입니다.
  지도가 작게 보여 경로 칩이 겹치면 칩을 위아래로 비켜 쌓습니다.
- **후보가 1개뿐**이면 비교한 결과가 아니므로 '맞춤 추천' 대신 회색 '유일한 경로'를 붙이고, "후보가 1개뿐" 안내를 카드 위에 둡니다. 이유 중 장점이 아닌 중립 사실(예: "신호등 5개를 지나요")은 ✓ 대신 회색 점으로 표시합니다.
- **허용 시간 초과 경로**는 추천에서 빠지지만 목록에 남아 직접 고를 수 있고, 이유가 함께 보입니다. 앱은 사용자의 조건을 말없이 완화하지 않습니다.
- **주행 안내**: 브랜드색 안내 카드에 다음 안내(큰 거리 숫자 + 도로 이름)와 그다음 안내, 아래에 남은 시간·거리. 일시정지·재개·종료만 있고, 설정·입력·평가는 없습니다. 안내 중에는 위쪽에 작은 `시연 중 · 실제 도로 안내가 아니에요` 표시가 항상 보입니다.
- **도착·평가**: 도착(또는 중도 종료) 뒤에만 평가를 받습니다. 표정 아이콘 3개 + 어려웠던 요소 선택(선택 사항, 건너뛰어도 됩니다). Android 뒤로 가기는 '마치기'와 같게 처리해 주행 기록이 사라지지 않습니다. 중도 종료 진행률은 도착하지 않았으면 99%를 넘지 않습니다.
- **측정값 표기**: 값·단위·출처·확인 여부를 구분하고, '0회'와 '정보 없음'을 다르게 보여줍니다. 사고다발구간 정보가 없는 것을 '안전'으로 보이지 않게 했습니다. 부담 계산에 쓰는 요소 중 확인되지 않은 것이 있으면 부담 수준을 **'보통 이상'처럼 하한으로** 표시합니다(6장).

## 4. 폴더 구조와 모듈 역할

```
mobile/
  App.tsx, index.ts          진입점: SafeArea · Navigation · Toast · 저장값 불러오기
  src/
    domain/                  화면·플랫폼과 무관한 순수 로직 (테스트 대상)
      types.ts               도메인 타입 (측정값·경로·추천 결과·기록…)
      factors.ts             운전 부담 요소 카탈로그 (이름·단위·설명·백엔드 코드)
      burden.ts              경로의 부담 수준 계산 (요소 중복 계산 방지)
      recommend.ts           추천 정책: 제한 → 허용 시간 → 부담 → 시간·거리·통행료
      preferences.ts         기본값 · 직접 설정 · 모의 학습을 합친 유효 선호
      learning.ts            평가 → 모의 개인화 조정 (동의한 경우만)
      records.ts, format.ts, geo.ts
    services/                화면이 의존하는 인터페이스 + 로컬 저장
      types.ts               PlaceSearchProvider · RouteProvider · RecommendationService
                             · NavigationSimulator · LocalRepository
      index.ts               ★ 서비스 조립 지점 (실제 구현으로 바꿀 때 고치는 곳)
      repository/            AsyncStorage / Memory / 오류 주입 / 저장값 검증
    mock/                    데모용 구현 (인터페이스를 그대로 구현)
      demoCity/              가상 도로망·지도 레이어·회전/차로 분류·경로 탐색·경로 조립,
                             decor.ts: 지도에 깔리는 골목·건물(정해진 난수, 경로 계산과 무관)
      mockPlaceSearch.ts, mockRouteProvider.ts, mockRecommendation.ts, navigationSimulator.ts
      scenario.ts, presets.ts  개발용 시나리오 스위치와 개인화 프리셋
    map/                     지도 렌더링 계층
      MapAdapter.ts          ★ 지도 컴포넌트가 받는 props 계약
      index.ts               ★ 지도 구현 교체 지점
      DemoMapView.tsx        SVG 가상 지도 (카메라·제스처·라벨·경로 칩·골목/건물 타일·경로 화살표)
      KakaoMapView.tsx       백엔드 모드의 카카오맵 (WebView). kakaoScene.ts: 보낼 장면 계산, kakaoMapHtml.ts: 지도 페이지

```

### 데이터 흐름

1. 검색 화면이 `PlaceSearchProvider.search` 로 장소를 찾습니다.
2. `tripStore` 가 `RouteProvider.findRoutes` 로 **도로 특성(후보·요소별 측정값)** 만 받습니다. 순위·이유는 여기서 만들지 않습니다.
3. `RecommendationService.recommend` 가 현재 `EffectivePreferences` 로 순위·이유·감수할 점을 만들어 **별도의 추천 결과**로 저장합니다.
4. 새 검색이나 설정 변경이 일어나면 예전 경로·이유가 남지 않도록 응답을 버리고(요청 취소/세대 비교) 추천을 다시 계산합니다. 설정이 바뀌면 화면에 알려줍니다.
5. 주행은 `NavigationSimulator` 가 선택한 경로의 점 위를 따라 진행합니다. 끝나면 동의한 경우에만 `LocalRepository` 에 기록합니다.

## 5. 후속 팀이 교체할 지점

화면 코드는 `src/services/types.ts` 의 인터페이스와 `src/map/MapAdapter.ts` 의 props 만 압니다.

| 바꿀 것 | 고칠 곳 | 인터페이스 |
|---|---|---|
| 장소 검색 | `services/index.ts` 의 `places` | `PlaceSearchProvider` (`search`, `listSamples`, `getDefaultOrigin`) |
| 경로 후보·도로 특성 | `routes` | `RouteProvider.findRoutes(origin, destination, { signal, preferences })` — 법규·통행 제한 경로는 `excluded` 로 알립니다. 후보가 0개여도 오류가 아닙니다. 성향으로 후보를 고르는 제공자는 `candidatesDependOnPreferences` 를 켜서, 설정이 바뀌면 후보를 다시 받아 오게 합니다. 실제 최단 시간은 `fastestDurationS` 로 함께 줍니다. |
| 추천·이유·개인화 모델 | `recommendation` | `RecommendationService.recommend({ candidates, preferences, excluded })` |
| 주행 안내 | `createSimulator` | `NavigationSimulator` (위치 기반 안내로 바꿀 때) |
| 로컬 저장 | `repository` | `LocalRepository` (보안 저장소로 바꾸거나 서버 동기화를 붙일 때) |
| 지도 | `map/index.ts` 의 `MapView` | `MapAdapterProps` — 경로선·마커·카메라 요청·가려진 영역(insets)·경로 선택 콜백 |

### 백엔드(`/v1/*`)와의 연결

`backend/README.md` 의 API 를 기준으로 한 매핑입니다. 백엔드는 이 앱의 도메인 정의(`domain/types.ts`, `domain/factors.ts`)에 맞춰져 있어서
**필드 이름(snake_case → camelCase)만 바꾸면** 됩니다. 이 변환은 `src/services/backend/` 에 있고(백엔드 모드), 기본 데모 모드에서는 호출하지 않습니다.

- **성향**: 첫 실행 설문부터 이어지는 유효 선호(직접 설정·동의한 모의 학습 포함)를 `profile` 로 보내 후보부터 성향을 반영합니다(`toApiProfile`). 점수에 쓰는 요소의 가중치만 0~5 로 잘라 보냅니다. 설정이 바뀌면 후보를 다시 받아 옵니다.
- **가장 빠른 길**: 성향을 보내면 서버가 가장 빠른 길을 후보에서 뺄 수 있어서, 각 경로의 `duration_s − extra_duration_s`(서버가 계산한 최단 시간)를 추가 시간의 기준으로 씁니다. 그 길이 후보에 없으면 어떤 후보도 '가장 빠름'이라고 하지 않고 안내를 띄웁니다(`fastest_not_included`).
- **지도**: 데모 지도는 가상 도시(위·경도 0,0) 범위에 묶여 있어서, 백엔드 모드에서는 카카오맵(`map/KakaoMapView.tsx`)을 씁니다. Kakao Maps JavaScript SDK 를 WebView 에 띄우고(`baseUrl` `http://localhost`), `MapAdapterProps` 를 장면 데이터로 바꿔(`kakaoScene.ts`) 페이지에 넘깁니다. 경로선·지나온 구간·출발/도착/차량 마커·경로 칩(누르면 선택)·카메라(전체/영역 맞추기/따라가기, 가려진 영역 반영)·주행 중 제스처 끄기를 지원합니다. 키가 없거나, 웹 미리보기(react-native-webview 미지원)이거나, 10초 안에 지도를 못 불러오면 경로 모양만 그리는 임시 지도(`map/RoutePreviewMap.tsx`)로 돌아갑니다. 경로는 백엔드 도로망(OpenStreetMap)에서 나오므로 지도 오른쪽 아래에 "시연용 경로 · 도로 자료 © OpenStreetMap"을 항상 보여 줍니다(임시 지도에도 같은 출처 표시).
- **오류**: `SAME_LOCATION`·`OUT_OF_SERVICE_AREA`·`ROUTE_NOT_FOUND` 는 다시 시도하지 않는 오류로, 연결 실패·시간 초과(15초)·5xx 는 다시 시도할 수 있는 오류로 보여 줍니다.
- **최근 목적지**: 데모 도시에서 저장된 최근 목적지는 백엔드로 경로를 찾을 수 없어서 백엔드 모드에서는 보여 주지 않습니다(`isServiceable`).

| 앱 | 백엔드 | 메모 |
|---|---|---|
| `PlaceSearchProvider.search` | `GET /v1/places/search` | `category` 는 앱의 `PlaceCategory` 값 그대로입니다. `lat`/`lng` 를 `location` 으로 묶습니다. 503 `PLACE_SEARCH_UNAVAILABLE` 은 검색 오류 상태(다시 시도)로 이어집니다. |
| `RouteProvider.findRoutes` | `POST /v1/routes/search` | `origin/destination/profile/max_routes`. 응답의 `polyline`(precision 5)을 디코딩해 `path: GeoPoint[]` 로 바꿉니다. `excluded` 도 같은 모양으로 옵니다(지금은 항상 빈 배열). |
| `RouteCandidate` | `routes[]` | `route_id`→`id`, `label`, `via`, `distance_m`→`distanceM`, `duration_s`→`durationS`, `toll`(지금은 항상 `unknown`), `factors`, `steps` |
| `RouteFactors` (`Measurement`) | `routes[].factors` | 모든 요소가 옵니다. `availability`·`value`·`unit`·`coverage`·`source`·`verification` 필드 이름까지 같습니다. |
| `GuidanceStep` | `routes[].steps[]` | `lat`/`lng`→`point`, `road_name`→`roadName`(이름 없는 도로는 `null` 이니 빈 문자열로), `road_class`→`roadClass`(대문자 → 소문자), `offset_m`→`offsetM`, `distance_m`→`lengthM`, `duration_s`→`durationS`, `turn_angle_deg`→`turnAngleDeg`, `unknown_factors`→`unknownFactors`. `maneuver`(`MERGE`/`DIVERGE` 포함)·`instruction`·`factors` 는 그대로입니다. |
| 오류 | `OUT_OF_SERVICE_AREA`, `SAME_LOCATION`, `ROUTE_NOT_FOUND` | `RouteProviderError` 코드(`UNSUPPORTED`, `SAME_LOCATION`…)나 '후보 0개'로 변환합니다. |
| 선호 | `profile.road_preference` / `hard_factors` / `easy_factors` / `weights` | 앱의 `roadTypePreference`(`highway`·`general`·`none`)는 `HIGHWAY`·`LOCAL`·`NONE`. 요소별 `relaxed·normal·avoid` 와 모의 학습 값은 `weights`(0~5)로 보내면 됩니다. 15개 요소 코드를 모두 받습니다. |
| 허용 추가 시간 | `extra_duration_s` | 앱이 이 값으로 허용 시간을 판단합니다(서버가 계산). |
| 회피 재탐색 | `POST /v1/routes/reroute` | 데모에는 경로 이탈이 없어 쓰지 않았습니다. |
| 기록 분석 | `POST /v1/profile/analyze` | 앱의 모의 개인화(`domain/learning.ts`)를 대체할 후보입니다. 백엔드는 실제 주행의 `encountered/deviations/hesitations` 를 받는 반면, 앱은 사용자가 직접 남긴 평가만 씁니다. |

**요소 코드 대응** (`domain/factors.ts` 의 `backendCode`)

15개 요소의 코드·단위·뜻이 백엔드와 같습니다. 백엔드도 `TURN_COUNT` 를 전체 회전 수로 세고 `UNPROTECTED_LEFT`·`U_TURN` 을
그 일부로 함께 세므로, 앱의 이중 계산 방지 규칙(전체 − 부분집합)을 그대로 쓰면 됩니다. 남은 차이는 아래뿐입니다.

| 항목 | 확인할 점 |
|---|---|
| `LANE_COUNT`, `ROAD_TYPE` | 백엔드도 점수에 쓰지 않는 참고 정보입니다. 도로 유형 선호는 `road_preference` 로 반영합니다. |
| 정보 없음 | 도로망 자료에 속성이 없는 구간은 `unknown`/`partial` 로 옵니다. 개발용 샘플 도로망은 `LANE_CHANGE` 를 일부러 비워 둡니다. |
| 통행료 | 자료가 없어 항상 `{ availability: 'unknown' }` 입니다. |
| 좌표 | 백엔드 도로망은 `.env.example` 기본값이면 강남역·역삼역 일대 실제 도로(OpenStreetMap, 약 2.4km × 2km), `GRAPH_PATH` 를 비우면 광주 일대 가상 격자입니다. 범위는 `GET /v1/service-area` 로 받습니다. 데모 지도의 가상 도시(위·경도 0,0 부근)를 보내면 `OUT_OF_SERVICE_AREA` 가 납니다. OSM 자료를 쓰는 화면에는 "© OpenStreetMap contributors" 표시가 필요합니다. |

## 6. 추천·개인화 규칙 (모의)

- 순서: ① 통행 제한(법규) 걸러내기 → ② 허용 추가 시간 안에서 운전 부담 최소화 → ③ 시간 → 거리 → 통행료 비교. 점수는 사용자에게 숫자로 보이지 않고 **낮음/보통/높음** 과 이유로만 보입니다.
- 정보가 빠진 요소: 순위를 매길 때 '정보 없음'은 다른 후보에서 **확인된 가장 나쁜 값**으로, '일부만 확인'은 확인 못 한 비율만큼 그 값을 더해 계산합니다(`recommend.ts` 의 `assumedWorst`). 정보가 빠졌다는 이유만으로 앞서지 않게 하려는 것이고, 어느 후보에서도 확인되지 않은 요소는 가정하지 않습니다. 화면에서는 이런 경로의 부담을 '낮음 이상'·'보통 이상'으로 표시합니다('높음'은 그대로).
- 설정의 '추천에 반영된 취향'은 내부 수치 대신 '조금 더 피해요'·'많이 더 피해요'·'조금 덜 피해요' 같은 문장으로 보여줍니다.
- 선호 우선순위: **사용자가 직접 정한 값**(상관없음/신경 쓰임/피하고 싶음) > **모의 학습 값**(동의한 경우, 직접 정하지 않은 요소만) > 기본값.
- 평가는 사용자가 '이 평가를 추천에 반영'을 켠 경우에만 반영합니다. 어려웠어요 +0.4, 쉬웠어요 -0.2(상한 +1.2 / 하한 -0.4). 기록이 적으면 '아직 취향을 알아가는 중이에요'로 표시하고, 더 어려운 길로 탐색을 유도하지 않습니다.
- 요소별 이중 계산 방지: 방향 전환(전체) / 비보호 좌회전·유턴(일부) / 급커브(구간)를 분리해 점수를 계산합니다. 차로 변경과 합류·분기도 따로 셉니다.
- 단속카메라는 요소에서 제외했습니다.

## 8. 개인정보와 저장

- 저장하는 값: 운전 성향·동의 여부, (동의 시) 주행 기록·평가, 평가로 조정된 취향(모의 개인화 결과), 최근 목적지. 모두 이 기기 안에만 있고 외부로 보내지 않습니다. 분석 도구·원격 로그가 없습니다.
- 이름·이메일·GPS 이력은 수집하지 않습니다. 위치 권한을 요청하지 않습니다.
- 저장 키는 모두 `newbiemap:v1:` 로 시작합니다. 설정에서 **주행 기록 삭제 / 추천에 반영된 취향 초기화 / 모든 사용자 데이터 삭제**를 따로 할 수 있고, '모든 데이터 삭제'는 위 키를 전부 지우고 첫 화면으로 돌아갑니다.
- 저장된 값을 **암호화하지 않습니다.** 읽을 수 없는 값은 버리고 알려줍니다.
- 기록 저장에 동의하지 않으면 주행·평가를 저장하지 않습니다(건너뛰기 상태의 기본값). 저장되는 기록의 종류(`kind`)는 항상 `simulation` 이라 나중에 실제 주행 기록과 섞이지 않습니다.

## 11. 알려진 한계

- 가상 도시가 작아 경로 3개가 비교적 단순합니다. 같은 구조로 더 큰 도로망을 넣으려면 `mock/demoCity/cityData.ts` 를 바꾸세요(`validateCity` 가 노드·구간·회전 정의가 서로 모순되지 않는지 검사합니다).
- 지도는 웹 미리보기와 Android 에뮬레이터에서 눈으로 확인했습니다. iOS 에서는 SVG 렌더링과 제스처를 확인하지 않았습니다.
- 주행 기록 화면의 부담 배지는 저장할 때의 수준만 남아 있어 '이상'(정보 일부 없음) 표시가 없습니다.
- 백엔드 모드는 개발용입니다. 경로는 강남역·역삼역 일대(약 3km × 3km) 실제 도로망에서만 찾을 수 있고, 그 밖의 장소는 서비스 지역이 아니라고 나옵니다. 도로망의 보호구역·사고다발·도로 폭 자료가 없어 해당 요소는 '정보 없음'입니다. 현재 위치는 아직 쓰지 않습니다.
- 도로망 범위(`samplePlaces.ts` 의 `SERVICE_BBOX`)는 `GET /v1/service-area` 값을 옮겨 둔 것입니다. 백엔드 도로망을 바꾸면 같이 고쳐야 합니다.
- 카카오맵의 칩·마커는 WebView 안에 그려서 앱의 글자 크기 설정을 따르지 않고, 화면 읽기에서 지도 전체가 하나의 요약 라벨로 읽힙니다. 카카오 로고(왼쪽 아래)는 아래 시트에 가려질 수 있습니다.
- 백엔드 모드에서 도로망과 아주 먼 좌표(예: 데모 도시의 0,0 부근)를 보내면 지금 백엔드가 응답하지 않는 문제가 있어(백엔드 쪽 수정 요청함), 앱은 15초 뒤 시간 초과로 알리고 그런 최근 목적지는 미리 걸러 냅니다.
- 안내 화면의 진행 배속 기본값은 14배입니다(약 2분에 끝). 개발용 시나리오에서 바꿀 수 있습니다.
- 지도의 골목·건물은 보기용 장식이라 실제로 지나갈 수 없습니다(경로는 주요 도로로만 계산).
- 글꼴은 기기의 시스템 글꼴을 씁니다. iOS·Android·기기 제조사에 따라 글자 모양이 조금 다릅니다(별도 글꼴 파일을 넣지 않았습니다).
- 안내를 시작할 때의 '시연용 안내예요' 시트는 앱을 켠 뒤 한 번만 뜹니다(확인 여부를 저장하지 않습니다).
- 세로 방향 휴대폰 화면만 검수했습니다. 태블릿(iPad 지원은 꺼 둠)·가로 방향·접이식 화면은 확인하지 않았습니다.

## 12. 실제 초보 운전자 테스트에서 확인할 것

- '예상 운전 부담 낮음/보통/높음'과 이유 문구를 **안전하다는 보장**으로 받아들이지 않는지.
- 추천 경로가 더 오래 걸려도 '왜 이 길인지'와 '대신 무엇을 감수하는지'를 이해하는지.
- 온보딩 질문(좌회전·차로 변경·합류 등 용어)을 이해하고, '잘 모르겠어요'를 부담 없이 고르는지.
- 허용 추가 시간(5/10/20분)이 실제로 감수 가능한 시간과 맞는지.
- 안내 화면에서 다음 동작을 한눈에 읽는지, 시연 표시를 놓치지 않거나 오히려 실제 안내로 오해하지 않는지.
- 평가('어려웠어요')를 남기고 다음 추천이 달라졌을 때 이유를 이해하는지, 직접 정한 설정과 충돌해 헷갈리지 않는지.

## 13. 백엔드 팀원 참고 (파일 변경 메모)

- **백엔드 파일은 수정·삭제·이동하지 않았습니다.** `app/`, `tests/`, `db/`, 루트 `README.md`, `requirements*.txt`, `pyproject.toml`, `.github/` 는 그대로입니다.
- 새로 추가한 것은 루트 `CLAUDE.md`(Claude Code 용 안내: 백엔드 설명 + `mobile/` 항목)와 `mobile/` 전체입니다.
- 지운 파일은 모두 **커밋된 적 없는 `mobile/` 안의 생성물·임시 파일**입니다. `create-expo-app` 템플릿이 만든 `.claude/`, `AGENTS.md`, `LICENSE` 와, 개발 중 임시로 만들었다 지운 `public/phone.html`, `src/mock/__tests__/tuning.test.ts` 입니다. **옮긴 파일은 없습니다.**
- CI(`.github/workflows/test.yml`)는 `pytest -q`(`testpaths = ["tests"]`)만 돌리므로 `mobile/` 은 검사 대상이 아닙니다. 앱 테스트는 `cd mobile && npm test` 입니다.
- 이후 화면 전체를 새 디자인으로 바꾸면서 `mobile/` 안의 파일을 많이 고쳤고, **추적 중인 파일을 지우거나 옮기지는 않았습니다.** 의존성은 `expo-haptics`, `expo-splash-screen` 이 늘었고 `app.json`(시작 화면·아이콘 색)과 `assets/` 의 아이콘이 바뀌었습니다.
- API 를 연결할 때 맞춰야 할 요소 정의 차이(`SHARP_TURN`, `LANE_CHANGE_TRAFFIC`, `TURN_COUNT` 이중 계산)는 5장에 있습니다. 백엔드에서 요소 코드·정의·단위를 바꾸면 5장 표도 함께 고쳐 주세요.
