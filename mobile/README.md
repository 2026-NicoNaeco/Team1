# 뉴비맵 (Newbiemap) — 모바일 앱 데모

> 조금 돌아가더라도, 나에게 운전 부담이 적은 길로.

운전이 서툰 사람이 **자기에게 부담이 적은 길**을 고르도록 돕는 내비게이션 앱의 **프런트엔드**입니다. 휴대폰(세로 화면)만 기준으로 만들었습니다.
React Native + Expo + TypeScript 로 만들었습니다. 이 저장소에서 확인한 것은 **웹 미리보기(휴대폰 크기)와 네이티브 번들 컴파일**까지이고, 실기기 실행은 아직 확인하지 않았습니다(10장).

> ⚠️ **데이터는 시연용입니다.** 지도·장소·경로·시간·통행료·교통량·추천·개인화는 모두 **모의 데이터/규칙**이고,
> 주행 안내는 선택한 경로를 따라 움직이는 화면입니다(실제 위치를 쓰지 않음). 실제 주행에 사용하지 마세요.
> '운전 부담이 낮음'은 안전하거나 사고가 없다는 뜻이 아닙니다. 앱은 안전 점수를 만들지 않습니다.
> 화면마다 '데모' 표시를 붙이지 않고, 아래 `시연 안내 지점` 에서만 알립니다(9장).

이 폴더(`mobile/`)는 저장소 루트의 백엔드(FastAPI, `app/`)와 **독립적으로** 동작합니다. 서버·API 키·로그인이 필요 없습니다.

## 1. 실행

필요한 것: **Node.js 20.19.4 이상**(React Native 0.86 의 요구 범위: 20.19.4+ / 22.13+ / 24.3+. 개발 환경은 Node 24.21 / npm 11.19), 휴대폰에서 열 때는 Expo Go 앱 또는 개발 빌드.

```bash
cd mobile
npm install
npm run web          # 웹 미리보기: http://localhost:8081  (휴대폰 크기 창에서 보세요. PC 폭 레이아웃은 만들지 않았습니다)
npm start            # Expo 개발 서버 — QR 로 Expo Go 에서 열기 / i(iOS) · a(Android) 키로 시뮬레이터 열기
npm test             # 단위 테스트 (jest, 10개 파일 / 193개 테스트)
npm run typecheck    # tsc --noEmit
```

- 단일 테스트: `npx jest src/domain/__tests__/burden.test.ts`, 이름으로: `npx jest -t "비보호 좌회전"`
- 휴대폰의 Expo Go 가 SDK 57 을 지원하지 않으면 개발 빌드(`npx expo run:android` / `npx expo run:ios`)가 필요합니다.
- 처음 켜면 온보딩이 나옵니다. 처음 상태로 돌아가려면 **설정 → 모든 사용자 데이터 삭제** 를 쓰세요.
- 의존성 버전은 `package.json` 에 고정했습니다. 새 패키지는 `npx expo install <이름>` 으로 SDK 에 맞는 버전을 설치하세요.

## 2. 무엇이 실제이고 무엇이 모의인가

| 영역 | 구분 | 설명 |
|---|---|---|
| 화면·이동·로딩/빈/오류/재시도 상태 | **실제** | 모든 화면과 상태 전환이 실제 코드로 동작합니다. |
| 온보딩(3단계)·운전 성향 설정·동의 | **실제** | 나중에 설정에서 모두 바꿀 수 있습니다. 건너뛰어도 쓸 수 있습니다. |
| 설정·기록·평가·개인화 결과 저장/삭제 | **실제** | 이 기기 안(AsyncStorage / 웹은 localStorage)에만 저장합니다. 앱을 다시 켜도 남습니다. **암호화하지 않습니다.** |
| 지도 | **모의** | 가상의 지역 '새싹시'를 SVG 로 그린 지도입니다(주요 도로 + 보기용 골목·건물). 끌기·확대·경로 선택이 됩니다. 지도 오른쪽 아래에 작게 '시연용 지도'가 보입니다. |
| 장소 검색 | **모의** | 준비된 장소 9곳 안에서만 찾습니다. 없는 장소를 만들어 내지 않으며, 검색 목록 아래에 "시연용이라 일부 장소만 검색돼요"라고 알립니다. |
| 경로 후보·도로 특성·시간·통행료·교통량 | **모의** | 가상 도로망에서 같은 입력이면 항상 같은 값을 계산합니다(결정적). 실시간 교통이 아닙니다. |
| 경로 추천·'예상 운전 부담' | **모의 규칙** | 단순한 규칙입니다. 실제 AI 모델이나 검증된 난이도 알고리즘이 아닙니다. |
| 개인화 | **모의 규칙** | 사용자가 직접 평가하고 동의한 경우에만, 고른 요소의 회피 정도를 조금 조정합니다. 직접 정한 값이 항상 우선합니다. |
| 주행 안내 | **경로 위 재생** | 선택한 경로를 따라 움직이는 화면입니다(기본 14배속). GPS·위치 권한을 쓰지 않습니다. |
| 로그인·서버·클라우드 동기화·백그라운드 위치·LLM | 없음 | 이번 범위에 넣지 않았습니다. |
| 실제 경로 엔진·도로 데이터·추천 모델 | 없음 | 후속 팀의 영역입니다. 연결 지점은 5장에 있습니다. |

앱 안의 **설정 → 앱 정보 → 시연 안내** 화면에도 같은 내용이 있습니다.

## 3. 화면과 흐름

```
온보딩(환영 → 질문 3개 → 요약·동의) ─▶ 홈(지도 + 내 운전 성향 + 갈 만한 곳) ─▶ 검색 ─▶ 경로 비교(3개) ─┬▶ 경로 상세 ─▶ 안내 시작
                                                                                              └▶ 안내 시작 ─▶ 도착·평가
                                   └ 탭: 지도 · 주행 기록(목록·상세·삭제) · 설정(성향·동의·삭제·앱 정보)
```

- **홈**: 지도 위에 검색창과 출발지, 아래 시트에 '내 운전 성향' 요약(눌러서 바꾸기)과 갈 만한 곳(최근 목적지가 있으면 그것).
- **경로 비교**: 경로 3개(A 가장 빠른 길 / B 고속도로 / C 회전이 적은 길). 카드마다 시간·추가 시간·**예상 운전 부담(낮음/보통/높음)**·이유 2~3개·감수할 점이 1개 이상 보입니다.
  카드를 눌러 **선택**하는 것, 앱이 **추천**한 경로(맞춤 추천 배지), **안내 시작**(아래 버튼)은 서로 다른 동작입니다. 큰 글자에서는 버튼이 세로로 쌓입니다.
- **허용 시간 초과 경로**는 추천에서 빠지지만 목록에 남아 직접 고를 수 있고, 이유가 함께 보입니다. 앱은 사용자의 조건을 말없이 완화하지 않습니다.
- **주행 안내**: 브랜드색 안내 카드에 다음 안내(큰 거리 숫자 + 도로 이름)와 그다음 안내, 아래에 남은 시간·거리. 일시정지·재개·종료만 있고, 설정·입력·평가는 없습니다. 안내 중에는 위쪽에 작은 `시연 중 · 실제 도로 안내가 아니에요` 표시가 항상 보입니다.
- **도착·평가**: 도착(또는 중도 종료) 뒤에만 평가를 받습니다. 표정 아이콘 3개 + 어려웠던 요소 선택(선택 사항, 건너뛰어도 됩니다).
- **측정값 표기**: 값·단위·출처·확인 여부를 구분하고, '0회'와 '정보 없음'을 다르게 보여줍니다. 사고다발구간 정보가 없는 것을 '안전'으로 보이지 않게 했습니다.

### 데이터 흐름

1. 검색 화면이 `PlaceSearchProvider.search` 로 장소를 찾습니다.
2. `tripStore` 가 `RouteProvider.findRoutes` 로 **도로 특성(후보·요소별 측정값)** 만 받습니다. 순위·이유는 여기서 만들지 않습니다.
3. `RecommendationService.recommend` 가 현재 `EffectivePreferences` 로 순위·이유·감수할 점을 만들어 **별도의 추천 결과**로 저장합니다.
4. 새 검색이나 설정 변경이 일어나면 예전 경로·이유가 남지 않도록 응답을 버리고(요청 취소/세대 비교) 추천을 다시 계산합니다. 설정이 바뀌면 화면에 알려줍니다.
5. 주행은 `NavigationSimulator` 가 선택한 경로의 점 위를 따라 진행합니다. 끝나면 동의한 경우에만 `LocalRepository` 에 기록합니다.

## 5. 후속 팀이 교체할 지점

화면 코드는 `src/services/types.ts` 의 인터페이스와 `src/map/MapAdapter.ts` 의 props 만 압니다.

| 바꿀 것 | 고칠 곳 | 인터페이스 |
|---|---|---|
| 장소 검색 | `services/index.ts` 의 `places` | `PlaceSearchProvider` (`search`, `listSamples`, `getDefaultOrigin`) |
| 경로 후보·도로 특성 | `routes` | `RouteProvider.findRoutes(origin, destination, { signal })` — 법규·통행 제한 경로는 `excluded` 로 알립니다. 후보가 0개여도 오류가 아닙니다. |
| 추천·이유·개인화 모델 | `recommendation` | `RecommendationService.recommend({ candidates, preferences, excluded })` |
| 주행 안내 | `createSimulator` | `NavigationSimulator` (위치 기반 안내로 바꿀 때) |
| 로컬 저장 | `repository` | `LocalRepository` (보안 저장소로 바꾸거나 서버 동기화를 붙일 때) |
| 지도 | `map/index.ts` 의 `MapView` | `MapAdapterProps` — 경로선·마커·카메라 요청·가려진 영역(insets)·경로 선택 콜백 |

### 백엔드(`/v1/*`)와의 연결

저장소 루트 `README.md` 의 API 를 기준으로 한 매핑 초안입니다. **이번 데모에서는 호출하지 않았고**, 아래 항목은 연결 전에 팀이 정의를 맞춰야 합니다.

| 앱 | 백엔드 | 메모 |
|---|---|---|
| `PlaceSearchProvider.search` | `GET /v1/places/search` | 503 `PLACE_SEARCH_UNAVAILABLE` 은 검색 오류 상태(다시 시도)로 이어집니다. |
| `RouteProvider.findRoutes` | `POST /v1/routes/search` | `origin/destination/profile/max_routes`. 응답의 `polyline`(precision 5)을 디코딩해 `GeoPoint[]` 로 바꿉니다. |
| 오류 | `OUT_OF_SERVICE_AREA`, `SAME_LOCATION`, `ROUTE_NOT_FOUND` | `RouteProviderError` 코드(`UNSUPPORTED`, `SAME_LOCATION`…)나 '후보 0개'로 변환합니다. |
| 선호 | `profile.road_preference` / `hard_factors` / `easy_factors` / `weights` | 앱의 `roadTypePreference`(`highway`·`general`·`none`)는 `HIGHWAY`·`LOCAL`·`NONE`. 요소별 `relaxed·normal·avoid` 와 모의 학습 값은 `weights`(0~5)로 보내면 됩니다. |
| 허용 추가 시간 | `extra_duration_s` | 앱이 이 값으로 허용 시간을 판단합니다(서버가 계산). |
| 안내 단계 | `steps[]` (`maneuver`, `turn_angle_deg`, `distance_m`, `duration_s`, `factors`) | 부호 규칙(양수=우회전)이 같습니다. 앱의 `MERGE`/`DIVERGE` 안내는 백엔드에 없습니다. |
| 회피 재탐색 | `POST /v1/routes/reroute` | 데모에는 경로 이탈이 없어 쓰지 않았습니다. |
| 기록 분석 | `POST /v1/profile/analyze` | 앱의 모의 개인화(`domain/learning.ts`)를 대체할 후보입니다. 백엔드는 실제 주행의 `encountered/deviations/hesitations` 를 받는 반면, 앱은 사용자가 직접 남긴 평가만 씁니다. |

**요소 코드 대응과 정의 차이** (`domain/factors.ts` 의 `backendCode`)

| 앱 요소 | 백엔드 코드 | 확인할 점 |
|---|---|---|
| `TRAFFIC_LIGHT`, `PROTECTED_ZONE`, `ROUNDABOUT`, `ACCIDENT_ZONE` | 같은 이름 | 백엔드는 0 과 '정보 없음'을 구분하지 않습니다. 앱은 구분해서 보여주므로 `unknown` 을 표현할 방법이 필요합니다. |
| `NARROW_ROAD`, `UNPAVED_ROAD` | 같은 이름 | 앱은 **km** 로 보여줍니다. 백엔드의 `count` 단위(구간 수 vs 길이)를 확인해야 합니다. |
| `TURN_COUNT` | `TURN_COUNT` | 앱은 **전체** 회전 횟수이고 비보호 좌회전·유턴은 그 일부입니다. 백엔드는 `U_TURN`·`SHARP_TURN` 이 일어날 때 `TURN_COUNT` 도 함께 1 씩 더하므로, 점수에 합칠 때 **이중 계산**을 피해야 합니다. |
| `U_TURN` | `U_TURN` | 같은 뜻입니다. |
| `SHARP_TURN` | `SHARP_TURN` | **뜻이 다릅니다.** 앱은 '급커브 구간', 백엔드는 '100° 이상 회전(교차로)' 입니다. |
| `MERGE_DIVERGE`, `LANE_CHANGE`, `TRAFFIC_VOLUME` | `LANE_CHANGE_TRAFFIC` 하나 | 백엔드는 합류·분기·차로 변경·교통량을 한 요소로 묶습니다. 앱은 세 가지를 따로 보여줍니다. |
| `UNPROTECTED_LEFT`, `LANE_COUNT`, `ROAD_TYPE` | 없음 | 도로 데이터에 필요한 속성입니다. 없으면 '정보 없음' 으로 보여줍니다. |
| 통행료 | 없음 | `TollInfo` 를 `unknown` 으로 두면 '통행료 정보 없음' 으로 보입니다. |

## 6. 추천·개인화 규칙 (모의)

- 순서: ① 통행 제한(법규) 걸러내기 → ② 허용 추가 시간 안에서 운전 부담 최소화 → ③ 시간 → 거리 → 통행료 비교. 점수는 사용자에게 숫자로 보이지 않고 **낮음/보통/높음** 과 이유로만 보입니다.
- 선호 우선순위: **사용자가 직접 정한 값**(상관없음/신경 쓰임/피하고 싶음) > **모의 학습 값**(동의한 경우, 직접 정하지 않은 요소만) > 기본값.
- 평가는 사용자가 '이 평가를 추천에 반영'을 켠 경우에만 반영합니다. 어려웠어요 +0.4, 쉬웠어요 -0.2(상한 +1.2 / 하한 -0.4). 기록이 적으면 '아직 취향을 알아가는 중이에요'로 표시하고, 더 어려운 길로 탐색을 유도하지 않습니다.
- 요소별 이중 계산 방지: 방향 전환(전체) / 비보호 좌회전·유턴(일부) / 급커브(구간)를 분리해 점수를 계산합니다. 차로 변경과 합류·분기도 따로 셉니다.
- 단속카메라는 요소에서 제외했습니다.

## 12. 실제 초보 운전자 테스트에서 확인할 것

- '예상 운전 부담 낮음/보통/높음'과 이유 문구를 **안전하다는 보장**으로 받아들이지 않는지.
- 추천 경로가 더 오래 걸려도 '왜 이 길인지'와 '대신 무엇을 감수하는지'를 이해하는지.
- 온보딩 질문(좌회전·차로 변경·합류 등 용어)을 이해하고, '잘 모르겠어요'를 부담 없이 고르는지.
- 허용 추가 시간(5/10/20분)이 실제로 감수 가능한 시간과 맞는지.
- 안내 화면에서 다음 동작을 한눈에 읽는지, 시연 표시를 놓치지 않거나 오히려 실제 안내로 오해하지 않는지.
- 평가('어려웠어요')를 남기고 다음 추천이 달라졌을 때 이유를 이해하는지, 직접 정한 설정과 충돌해 헷갈리지 않는지.

## 13. 백엔드 팀원 참고 (파일 변경 메모)

- **백엔드 파일은 수정·삭제·이동하지 않았습니다.** `app/`, `tests/`, `db/`, 루트 `README.md`, `requirements*.txt`, `pyproject.toml`, `.github/` 는 그대로입니다.
- 새로 추가한 것은 루트 `CLAUDE.md`(Claude Code 용 안내: 백엔드 설명 + `mobile/` 항목)와 `mobile/` 전체입니다.
- 지운 파일은 모두 **커밋된 적 없는 `mobile/` 안의 생성물·임시 파일**입니다. `create-expo-app` 템플릿이 만든 `.claude/`, `AGENTS.md`, `LICENSE` 와, 개발 중 임시로 만들었다 지운 `public/phone.html`, `src/mock/__tests__/tuning.test.ts` 입니다. **옮긴 파일은 없습니다.**
- CI(`.github/workflows/test.yml`)는 `pytest -q`(`testpaths = ["tests"]`)만 돌리므로 `mobile/` 은 검사 대상이 아닙니다. 앱 테스트는 `cd mobile && npm test` 입니다.
- 이후 화면 전체를 새 디자인으로 바꾸면서 `mobile/` 안의 파일을 많이 고쳤고, **추적 중인 파일을 지우거나 옮기지는 않았습니다.** 의존성은 `expo-haptics`, `expo-splash-screen` 이 늘었고 `app.json`(시작 화면·아이콘 색)과 `assets/` 의 아이콘이 바뀌었습니다.
- API 를 연결할 때 맞춰야 할 요소 정의 차이(`SHARP_TURN`, `LANE_CHANGE_TRAFFIC`, `TURN_COUNT` 이중 계산)는 5장에 있습니다. 백엔드에서 요소 코드·정의·단위를 바꾸면 5장 표도 함께 고쳐 주세요.
